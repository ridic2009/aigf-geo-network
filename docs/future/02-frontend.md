# 02 — Frontend Architecture

React 19 + TypeScript 5 + Vite 6. SPA, отдаётся статикой с app-1, обращается
к `/api/v1` того же origin.

## Структура — Feature-Sliced Design

```
/client/src
  app/          точка входа, роутер, провайдеры, error boundary
  pages/        экраны по маршрутам
  widgets/      составные блоки (site-table, health-board, page-editor)
  features/     пользовательские действия (publish-site, revoke-session)
  entities/     доменные модели + их API (site, page, product, user, job)
  shared/
    api/        http-клиент, сгенерированные типы, обработка ошибок
    ui/         дизайн-система (Button, Table, StatusPill, …)
    lib/        форматирование, даты, guard-функции
    config/     рантайм-конфиг, фичефлаги
```

Импорт разрешён **только вниз**:

```
app  →  pages  →  widgets  →  features  →  entities  →  shared
```

Проверяется `eslint-plugin-boundaries`; нарушение валит сборку, а не остаётся
на совести ревьюера. Обоснование выбора FSD — [ADR 0011](../adr/0011-frontend-stack.md).

Внутри слайса — одинаковая раскладка:

```
entities/site/
  api/        useSites, useSite, useUpdateSite
  model/      типы, селекторы, производные вычисления
  ui/         SiteBadge, SiteAvatar — презентация сущности
  index.ts    публичный экспорт слайса
```

За пределы слайса видно только то, что экспортировано из `index.ts`. Импорт
вглубь чужого слайса запрещён тем же линтером.

## Состояние — четыре вида, четыре механизма

| Вид | Механизм | Правило |
| --- | --- | --- |
| Серверные данные | **TanStack Query** | единственный источник; не копируется в стор |
| Состояние URL | **React Router** (searchParams) | фильтры, страница, вкладка, выбранный сайт — всё шарится ссылкой |
| Локальный UI | `useState` / `useReducer` | не поднимается выше, чем нужно |
| Глобальный UI | **Zustand**, один маленький стор | тема, состояние сайдбара, палитра команд |

### Жёсткое правило

**Если данные пришли из API — они не попадают в Zustand.**

Это убивает целый класс багов «в сторе лежит устаревшая копия». Кеш, инвалидация
и статусы загрузки — ответственность Query, а не наша.

Ключи кеша описаны централизованно в `shared/api/query-keys.ts`; строки руками
не собираются:

```ts
export const queryKeys = {
  sites: {
    all: ['sites'] as const,
    list: (filters: SiteFilters) => ['sites', 'list', filters] as const,
    detail: (id: string) => ['sites', 'detail', id] as const,
  },
} as const;
```

Иначе инвалидация промахивается мимо кеша, и пользователь видит старые данные
после успешного сохранения — самый дорогой сорт бага в панели управления.

### Состояние в URL — почему это правило, а не вкус

Отчёт SEO-аудита, отфильтрованный по сайту и severity, должен открываться по
ссылке в чате. Фильтры в React-состоянии этого не позволяют, и обходится это
скриншотами.

## API-слой

```
OpenAPI 3.1 (генерируется из PHP-атрибутов)
   └→ openapi-typescript → shared/api/schema.d.ts   (типы, руками не правятся)
        └→ openapi-fetch + httpClient                (единственная точка сетевых вызовов)
             └→ entities/<x>/api/*.ts                (useSites, useSite, useUpdateSite)
                  └→ компоненты
```

`httpClient` централизует:

* `credentials: 'include'` и заголовок CSRF;
* `X-Request-Id` — тот же идентификатор попадает в серверный лог;
* разбор `problem+json` в типизированный `AppError` с полем `code`;
* 401 → переход на логин с сохранением адреса возврата;
* 403 → тост; `StepUpRequired` → диалог подтверждения;
* 429 → показ `Retry-After` вместо молчаливого провала;
* ретраи только для идемпотентных GET;
* таймауты.

**Компонент никогда не вызывает `fetch` напрямую** — правило ESLint, не
соглашение.

## Формы

`react-hook-form` + `zod`. Серверные ошибки раскладываются по полям формы через
`code`, а не показываются одним общим тостом:

```ts
if (error.code === 'content.page.slug_taken') {
  form.setError('slug', { message: t('errors.slug_taken') });
}
```

Пользователь должен видеть проблему там, где её исправляют.

## Правила компонентов

* Компонент — либо **презентационный** (props → разметка, без запросов), либо
  **контейнерный** (хуки данных + композиция). Не смешивать.
* Бизнес-вычисления живут в `entities/<x>/model`, не в JSX.
* Максимум ~150 строк; больше — разбить.
* Нет `dangerouslySetInnerHTML`, кроме одного аудированного `<Markdown>`.
* **Каждый компонент, показывающий данные, обязан иметь состояния `loading`,
  `empty` и `error`.** Проверяется на ревью, покрывается историями Storybook.
* Именование: компоненты `PascalCase`, хуки `useX`, обработчики `handleX`,
  пропсы-колбэки `onX`. Именованные экспорты, без `default`.

## Маршрутизация

React Router 7, ленивые чанки на уровне `pages/`.

Права влияют на маршруты: недоступный раздел не рендерится и не появляется в
навигации. **Но реальная проверка всё равно на сервере** — клиентская нужна
только чтобы не показывать заведомо неработающие кнопки. Скрытая кнопка не
является контролем доступа.

## Тестирование

| Уровень | Чем | Что |
| --- | --- | --- |
| Unit | Vitest | селекторы, форматирование, преобразования |
| Компоненты | Testing Library | состояния loading/empty/error, доступность |
| E2E | Playwright | вход, создание сайта, правка, публикация, откат, отзыв сессии |

Визуальные регрессии — скриншот-тесты Playwright на дизайн-систему в обеих темах.
