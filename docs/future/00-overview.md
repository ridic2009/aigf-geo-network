# 00 — Architecture Overview

> Часть проектной документации платформы управления сетью сайтов.
> Описывает **целевую** систему. Работающая сегодня система описана
> в [docs/architecture.md](../architecture.md) и будет удалена вместе с ней.

## Контекст

Сегодня в репозитории живёт генератор статики: Cecil 9 + Twig, контент в
Markdown/YAML (`content/<geo>/`, `config/geos/<geo>.yml`, `data/products/`),
редактор MiniCMS Studio — ~2 500 строк PHP без фреймворка
(`scripts/php/Studio*.php`) и ~1 700 строк vanilla JS (`studio/public/app.js`),
состояние в JSON-файле `.studio/state.json`, сессии в файлах, права — три роли,
захардкоженные в `StudioAuth.php`. Работает 4 GEO.

Модель упирается в потолок: файловое состояние не выдержит 100 сайтов и
25 человек, нет транзакций, нет отзыва сессий, нет RBAC, нет мониторинга,
бизнес-логика смешана с HTTP-слоем в `studio/public/index.php` (229 строк
на один `switch`).

Цель — фундамент, который доживёт до 100 сайтов без переписывания архитектуры.

Горизонт планирования: **100 сайтов, 25 пользователей, 12 месяцев.**

### Принятый риск

Slim без готового security-слоя означает, что sessions, RBAC, CSRF и rate
limiting пишутся руками — это самая частая причина уязвимостей в самописных
панелях. Компенсация: [04-security.md](04-security.md) фиксирует конкретную
проверенную библиотеку на каждый security-критичный примитив; фаза 1
[roadmap](../roadmap.md) завершается security-review по OWASP ASVS L2, и до его
прохождения сверху ничего не строится.

└──────┬──────────────────────────────────────┬────────────────┘
       │                                      │
       │ visitors / Googlebot                 │ сотрудники

         │                            ┌──────▼────────────────┐
         └────────────────────────────│  PostgreSQL 16        │

                                      └──────┬────────────────┘

                                      │  backup (offsite)     │
                                      └───────────────────────┘

## Четыре плоскости

Разделение намеренное: оно определяет, что именно ломается при каждом отказе.

| Плоскость | Что это | Отказ приводит к |
| --- | --- | --- |
| **Control plane** | app-1 + PostgreSQL: панель, API, воркеры | нельзя редактировать и публиковать; сайты продолжают работать |
| **Build plane** | воркеры: экспорт БД → файлы → Cecil → артефакт | нельзя выкатывать новое; сайты работают |
| **Serving plane** | web-1/web-2 + Cloudflare: только статика | падение одного узла — переключение на второй |
| **Observability plane** | проб-движок + внешние точки наблюдения | не видно состояния; всё остальное работает |

**Главное свойство: serving plane не имеет зависимостей от control plane.**
Сайты приносят деньги, панель — нет. Падение БД, приложения или воркера не должно
ронять трафик. Подробности и альтернативы — [ADR 0001](../adr/0001-static-serving-plane.md).
