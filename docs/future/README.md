# Заметки на будущее — НЕ РЕАЛИЗОВАНО

> **Действующая архитектура описана в [docs/architecture.md](../architecture.md).**
> Файлы в этом каталоге её не описывают и не отменяют.

Черновик проектирования перехода на полноценное веб-приложение (PHP + React,
PostgreSQL как источник правды вместо Markdown/YAML). Работа остановлена по
решению от 2026-09-16: **остаёмся на текущей архитектуре** — Cecil + Twig,
MiniCMS Studio, контент в файлах.

## Зафиксированные тогда решения

Если к теме вернутся, эти вопросы уже обсуждались и закрывались так:

| Вопрос | Решение |
| --- | --- |
| Публичные сайты | остаются статикой, движок Cecil сохраняется |
| Backend | PHP 8.3 + Slim 4, без Laravel/Symfony |
| Frontend | React + TypeScript + Vite |
| Источник правды | PostgreSQL 16, экспорт в файлы при сборке |
| Хостинг | текущий провайдер, бюджет ≤ $400/мес |
| Горизонт | 100 сайтов, 25 пользователей |

## Предостережения

* **Ссылки внутри файлов ведут в никуда.** Они указывают на ненаписанные разделы
  (`04-security.md`, `../adr/`, `../standards/`) и на прежнее расположение
  `docs/architecture/`. Чинить их сейчас незачем.
* Описание текущего состояния во вводной части `00-overview.md` актуально на
  сентябрь 2026 и устареет по мере развития Studio.
* Главный риск, зафиксированный при проектировании: Slim без готового
  security-слоя означает, что сессии, RBAC, CSRF и rate limiting пишутся руками.
  Это осталось непроработанным — раздел по безопасности написан не был.
